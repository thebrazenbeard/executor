## Authority and persistence
`vera_assurance.EffectFence` owns durable single-use effect IDs, persisted states and ambiguity barriers in the Vera Mono state directory; `vera_core.LifecycleEffectRecovery` requires independently verified reconciliation proof, trusted issuer currentness and the outbound audit chain. Only `QualifiedVeraRuntime` + accepted lifecycle/authority may execute an effect. Executor's existing in-memory `EffectLedger` and experimental `DurableEffectHoldJournal` are **not equivalent authorities**. Do not wire the latter in parallel with Mono, publish dual COMMITTED flags, or use its Node >=22 `node:sqlite` module as a workaround for the Node >=20 package engine.

## Safe host integration sequence (not performed)
1. Owner-selected, trusted Vera Mono state root **already provisioned and verified**, with unchanged exact installation/source/route digest; qualified Mono runtime opens it and verifies fence/audit/recovery currentness, no missing DB/root rollback or foreign replacement.
2. Receiver owns exact effect/task ID, canonical request digest, source task-journal head, caller scope, generation, `connectedAt` and one-use nonce. Cross-check the currently enrolled Executor socket identity under gateway lock. Transport callbacks are NOT Mono effect receipts.
3. Qualified Mono effect gateway reserves/claims **single-use** dispatch under existing lifecycle + authority checks, recording intent durably *before* any device outbound dispatch. Executor accepts only one narrowly scoped request, not autonomous retry. Unknown/disconnect/retirement → Mono `ATTEMPTED_UNKNOWN` or unresolved `EXECUTING`; block any new protected work until recovery.
4. Read the *destination application* journal through an authenticated, generation-bound reply and verify exact effect ID/request/result digest and durable consumer history. A WebSocket send callback, HTTP202, a self-reported VirtIO `ok`, an Ollama inventory digest or a forged `COMMITTED` field are not sufficient.
5. Only the Mono trusted reconciliation verifier may clear an ambiguous fence, and only from separately verified external proof. Reread Mono fence/audit/task currentness after restart. No blind re-execution of unknown operations.
6. Require Patrick's separately scoped authority for any installed gateway changes, VeraOS normal-resident activation, model inference or protected effects.

## New read-only Executor source boundary
`src/mono-effect-readback.ts` is **Node20-compatible by construction** (pure JavaScript checks; no SQLite or provider/HTTP import). The caller must still independently authenticate any Mono readback. The function checks pinned Mono source revision, target device `generation/connectedAt`, exact effect ID and request SHA256, recognized fence states, result/reconciliation digest shape and false completion claims. It returns HOLD or SOURCE_OBSERVATION_ONLY. **Every result sets dispatch/retry, reconciliation and application/external effect proof false.** It never calls Mono, modifies its database, signs data or promotes a terminal state.
